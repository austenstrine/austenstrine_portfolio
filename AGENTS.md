# AGENTS

Start here for this repo.

1. Run `./bin/agent-cli` (or `./bin/agent-cli orient`) once before exploring.
2. Prefer `./bin/agent-cli <subcommand> [--json]` over re-reading `package.json`, `.dsshrc`, compose files, seed paths, or guessing npm/dssh commands.
3. Subcommands: `orient` `layout` `scripts` `env` `docker` `seed` `helpers` — see `./bin/agent-cli --help`.
4. Git (this portfolio): integrate on **`development`** (based on `master` — `master` is stable/deploy, not the agent default). Feature branches: `feature/<user>/development/<name>` (user usually `als`); always create a **local** branch (GitKraken). Merge features into `development` with no PR; leave `master` alone unless asked. After peers land on `development`, rebase/pull the feature onto it. After pushing `development`, sync Austen’s local checked-out `development`. On a shared VM, edit via `git worktree add`, not the shared checkout in place. Full prefs: `docs/git-commit-preferences.md` (mirrored in `.cursor/rules/git-commit-preferences.mdc`).
5. Sibling tool remotes are usually **`master`** (commit/merge without review there is OK) — confirm with `git ls-remote --symref origin HEAD` rather than a local branch name. That is **not** this portfolio’s landing rule.
6. `./dssh` needs [developers-sugary-shell-helper](https://github.com/austenstrine/developers-sugary-shell-helper): run that repo’s `./install.sh` and keep `~/.local/bin` on `PATH`, or clone as a sibling / set `DSSH_BIN`. See README “Third-party tools”.
7. Assume async peers always. Before contested edits: `./bin/agent-coord` claim / negotiate / release (sibling `~/Development/agent-coord`, or `~/.local/bin/agent-coord` via that repo’s `./install.sh`, or `AGENT_COORD_BIN`). HELLO discourse flag `0x01`. See Place et Marque store `workflows/agent-coordination.md` and `principles/agent-coordination-discourse.md`.
8. **Local backend / CRM restarts:** agents may restart `./dssh backend` / `portfolio-api` and `./dssh crm` / `portfolio-crm` when needed, but must run `dssh backend restart; dssh logs backend` or `dssh crm restart; dssh logs crm` in the **user's Cursor terminal** in this window (prefer the active backend/CRM/dssh terminal). Prefer `dssh logs <target>` (not `dssh <target> logs` as the documented form). If the agent cannot drive that terminal, prompt the user to run it and wait until they indicate done before continuing work that depends on the new process. Do not silently `docker stop|rm|restart portfolio-api` or `portfolio-crm` in the background — that confuses the user's log stream with SIGTERM. SIGTERM during a proper user-terminal restart is expected (old container replace), not a Nest/Next bug. See `.cursor/rules/dssh-backend-ownership.mdc`.
